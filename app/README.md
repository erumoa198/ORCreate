# Navi Beauty App（プロトタイプ）

株式会社Navi の 2C向け美容アプリ。**眉・お肌の悩みを診断 → アドバイス → おすすめメニュー/商品 → QRコードでお客様のスマホに保存**、という体験を中心に、メニュー紹介・商品紹介・眉毛の豆知識を備えたモバイル特化Webアプリです。

> このフォルダ（`app/`）は **独立・隔離** されています。既存サイトには一切影響しません。不要になれば `app/` フォルダを削除するだけで完全に消せます。

---

## 1. 特徴

- **モバイル特化 / 縦横レスポンシブ** … iPhone・Android・iPad、縦向き/横向きどちらでも最適表示。ボトムタブバーでアプリ風の操作感。
- **PWA対応** … スマホのホーム画面に追加すると全画面アプリのように動作。`manifest` + Service Worker で簡易オフライン対応。
- **フレームワーク非依存（Vanilla JS）** … ビルド不要。静的ファイルなので、自社サーバー/ドメインにそのままアップロードできます。
- **バックエンド不要** … 診断結果はURLに内包され、QRから開くだけで再表示。サーバー側の保存が不要。
- **データ駆動** … 診断・メニュー・商品・豆知識はすべて `data/*.json`。エンジニアでなくても内容を増やせます。
- **エディトリアルデザイン** … 雑誌的なタイプ主導の構成。ウォームボーン × ダスティクレイローズ × 墨。絵文字を使わずSVGラインアイコンで統一（詳細は §3）。

## 2. 確認方法（2通り）

### A. 単一HTMLで確認（サーバー不要・実機向け）
`app/navi-beauty-standalone.html` を **ダブルクリック**するだけ。CSS/JS/データ/英字フォントを1ファイルに同梱しているため `file://` 直開きで動きます。スマホへAirDrop/メール等で送れば実機確認も可能（和文は端末フォント＝iPhone/Macはヒラギノで表示）。

修正後の再生成：
```bash
python3 app/build-standalone.py   # → app/navi-beauty-standalone.html を更新
```

### B. ローカルサーバーで確認（本番に近い完全版）
通常版は `fetch` でJSONを読むため、簡易サーバー経由で開きます（フォント自己ホスト・PWAも含む）。
```bash
cd app
python3 -m http.server 8123
# ブラウザで http://127.0.0.1:8123/ を開く（スマホ表示でご確認ください）
```

## 3. デザインの方向性（エディトリアル）

最新のおしゃれなアプリUIトレンドを踏まえ、**雑誌（エディトリアル）的**な設計にしています。

- **タイプ主導**：大胆なディスプレイセリフ（Cormorant Garamond）× 和文明朝（Shippori Mincho）× クリーンなラベル（Inter）× 本文ゴシック（Zen Kaku Gothic New）。
- **絵文字ゼロ**：すべて自作のSVGラインアイコン／ラインアートモチーフ。
- **画像主導**：写真の差し込みを前提に、現状は上質なデュオトーン＋グレイン質感の「カバー」で表現（本番で実写に差し替え可能）。
- **余白と階層**：ハッシュ目次・通し番号・ヘアライン区切りで、情報を“羅列”せず構成。
- **アプリらしい体験**：診断は1問1画面の没入フロー、横スクロールのカバーカード、結果は設計されたQRパネル。
- **配色**：ウォームボーン × ダスティクレイローズ × 墨（Naviの世界観を上質に再構成）。CTAのLINEグリーンのみブランド既定色。
- **フォントは自己ホスト**：`app/fonts/` に同梱。外部CDN非依存でオフライン動作＆本番でも自己完結。

## 4. フォルダ構成

```
app/
├── index.html              # アプリ本体（1ページSPA / ハッシュルーティング）
├── manifest.webmanifest    # PWA設定
├── sw.js                   # Service Worker（オフラインキャッシュ）
├── css/
│   ├── app.css             # デザインシステム（色・余白・各画面）
│   └── fonts.css           # 自己ホストフォント定義（@font-face）
├── js/
│   ├── app.js              # ルーター・データ・診断エンジン・画面描画・SVGアイコン
│   ├── qr.js               # QRコード生成ラッパー
│   └── vendor/qrcode.js    # QR生成ライブラリ（qrcode-generator, MITライセンス）
├── data/
│   ├── diagnoses.json      # 診断（質問・スコア・結果）★悩み別パターンを増やす場所
│   ├── menus.json          # 施術メニュー（アートメイク/エステ）
│   ├── products.json       # 商品（オンラインショップ）
│   └── tips.json           # 眉毛の豆知識（ミニ知識＋コラム）
├── fonts/                  # 自己ホストwoff2（Cormorant/Inter/Shippori/Zen Kaku）
├── icons/                  # PWAアイコン＋グレイン質感テクスチャ
└── README.md               # このファイル
```

### 写真の差し込み方（本番）
各カバーは `.cover.cover--*`（デュオトーン）で表現しています。本番では `background-image` に実写を入れるだけで、レイアウトはそのまま画像主導の見た目になります（眉・施術例・商品写真など）。

## 5. 診断パターンの増やし方（悩み別に多数つくる）

`data/diagnoses.json` の `diagnoses` 配列に1ブロック追加するだけで、新しい診断が増えます。

```jsonc
{
  "id": "lip",                         // 一意なID（URLに使われる）
  "title": "リップ診断",
  "subtitle": "なりたい唇の印象から提案",
  "tag": "リップ",                     // 一覧に出る小ラベル（任意）
  "minutes": 1,
  "questions": [
    {
      "q": "質問文",
      "options": [
        { "label": "選択肢A", "scores": { "typeX": 2, "typeY": 1 } },
        { "label": "選択肢B", "scores": { "typeY": 3 } }
      ]
    }
  ],
  "results": [
    {
      "id": "typeX",                   // ↑scoresのキーと一致させる
      "title": "結果タイトル",
      "catch": "ひとことキャッチ",
      "summary": "結果の説明文",
      "advice": ["アドバイス1", "アドバイス2"],
      "menus": ["lipartmake"],         // menus.json のID（おすすめメニュー）
      "products": ["serum-moist"]      // products.json のID（おすすめ商品）
    }
  ]
}
```

**仕組み**：各選択肢の `scores` を合計し、最も高い結果タイプを表示します。結果に紐づく `menus`/`products` のIDから、おすすめが自動で表示されます。メニュー・商品を増やす場合は `menus.json` / `products.json` にIDを追加してください。

## 6. QRコードの仕組み

診断結果は `#/r/<エンコード済みデータ>` というURLに結果情報を埋め込みます。QRはこのURLを指すため、

1. アプリで診断 → 結果画面のQRを表示
2. お客様が自分のスマホで読み込む
3. 同じ結果ページが開く → ブックマークすればいつでも見返せる

…という流れが **バックエンドなし** で成立します。本番では、この結果ページに予約/LINE導線やアクセス計測を足すだけで運用できます。

## 8. 追加でおすすめの機能（提案）

すぐに乗せられる順で。すべて今の構成（静的＋データ駆動）の延長で実装できます。

1. **LINE連携** … 結果を公式LINEに送る / 友だち追加で結果保存。来店前カウンセリングがスムーズに。
2. **Web予約 連携** … 結果のおすすめメニューから、そのまま予約フォーム/予約システムへ。
3. **クーポン・初回特典** … 診断完了でクーポンQRを発行（来店動機・効果測定）。
4. **Before/After ギャラリー** … 施術例を悩み別に。診断結果からも関連症例へ誘導。
5. **店舗・アクセス情報** … 地図・営業時間・スタッフ紹介（梅田クリニック）。
6. **多言語対応** … 日本語/英語/中国語。インバウンド集客に。
7. **AIカウンセリングチャット** … 悩みを自由入力 → おすすめ診断/メニューへ誘導（Naviの「AIコンサル事業部」とも親和）。
8. **顔写真でのシミュレーション** … 眉デザインの重ね表示（要・撮影/解析機能）。
9. **アクセス解析** … どの診断・結果・メニューが人気かを計測し、商品/メニュー企画に反映。

## 9. 今後の拡張ロードマップ（案）

- **フェーズ1（今回）**：診断体験のMVP + 各ページのUI/UX確認。静的Webで隔離検証。
- **フェーズ2**：本番環境に合わせて、LINE/予約/EC/解析を接続。料金・商品データを実データ化。
- **フェーズ3**：会員/マイページ（診断履歴・お気に入り・リタッチ時期のお知らせ）。
- **フェーズ4**：ネイティブアプリ化（Capacitor等でこのWebをラップ → App Store / Google Play 配信）。プッシュ通知でリピート促進。
